iBatcher 1.1.0
======================

Назначение
----------
Портативная Windows-утилита для массового выполнения REST-запросов.
Не привязана к конкретному типу документа.

Запуск
------
1. Запустите "iBatcher.exe".
2. Программа откроет локальную страницу в браузере.
3. Укажите login-запрос, основной запрос, JSON-тело и параметры запуска.
4. Нажмите "Проверить 1 запрос".
5. После успешной проверки запустите нужное количество запросов.
6. Для полного закрытия нажмите "Закрыть программу" в правом верхнем углу.

После первого запуска значок папки iBatcher обновится автоматически.
Если Проводник ещё показывает обычную папку, нажмите F5.

Важно
-----
- Проверочный запрос является реальным и может создать документ.
- Пароли не сохраняются в профилях.
- Интерфейс доступен только локально на 127.0.0.1.
- Проверку HTTPS-сертификата рекомендуется оставлять включённой.
- Для http://localhost программа корректирует Secure-cookie, имитируя поведение Postman.

Проверка ответа
---------------
По умолчанию программа считает ответ бизнес-ошибкой, если в JSON есть
непустое поле $.errorCode, и показывает текст из $.errorText.
Успешное создание подтверждается непустым полем $.id.

После проверочного запроса раскройте блок "Проверочный запрос и ответ":
в нём показаны фактически отправленный JSON, HTTP-статус и полный ответ сервера.
Это помогает проверить подстановку уникальных значений и причину ошибки.
Блок доступен только в текущем сеансе интерфейса; в профиль эти данные не сохраняются.

Эти пути сохраняются в каждом профиле и могут быть изменены для другого API.
Если API не возвращает идентификатор, очистите поле "Подтверждение успеха" —
тогда при отсутствии бизнес-ошибки будет достаточно статуса HTTP 2xx.

Динамические поля
-----------------
Путь указывается в формате:
  $.externalId
  $.payment.operationId
  $.items[0].id

Поддерживаются UUID, счётчики, время ISO и случайные строки.
Если уникальные значения не нужны, оставьте список динамических полей пустым.

Профили и отчёты
----------------
Профили и отчёты находятся в папке data рядом с EXE:
  data\profiles
  data\reports

Папку отчётов можно открыть кнопкой "Отчёты".

Пауза и продолжение
-------------------
Кнопка "Пауза" прекращает выдачу новых запросов и дожидается текущих.
Кнопка "Продолжить прогон" продолжает оставшиеся запросы с сохранёнными
настройками. После перезапуска EXE пароль нужно ввести повторно.
Состояние прогона хранится в data\runs рядом с EXE; не удаляйте эту папку,
пока прогон не завершён. Отчёт создаётся для каждого этапа запуска.

Если компьютер выключился или произошёл таймаут, некоторые запросы могут
получить статус "результат неизвестен". Они не отправляются повторно
автоматически: сервер мог уже создать документ. Проверьте их по данным ДБО.
Для POST-запросов таймауты и HTTP 5xx также не повторяются автоматически.

Системные требования
--------------------
Windows 10/11, доступ к нужному API или корпоративному VPN.
Python, PyCharm и дополнительные библиотеки пользователю не требуются.
